  SOXL 분할매수 전략 — 파라미터 수정 절차 (Parameter Update Guide)

최종 업데이트: 2026-05-25

【이 문서의 목적】

  이 문서는 SOXL 장기 분할매수 전략을 운영하는 누구든
  파라미터 수정 절차를 정확히 이해하고 실수 없이 실행할 수
  있도록 작성된 운영 매뉴얼입니다.

  전략 개요:
    - 종목     : SOXL (반도체 3배 레버리지 ETF)
    - 방식     : VIX 지수 + 시그마(변동성) 기반 분할매수
    - 목표     : 약 1년간 24회 진입 (월 평균 2회) 후 1년 홀딩
    - 운용 기간 : ~2027년 5월 매수 완료 → 2028년 5월 청산 예정


----------------------------------------------------------------
【등장하는 파일 3가지와 역할】

  ┌──────────────────────────────────────────────────────────────┐
  │  파일명                        역할              직접 편집     │
  ├──────────────────────────────────────────────────────────────┤
  │  SOXL_VIX_SIGMA_BACKTEST.py   최적 배수 탐색 엔진  ✅ 여기만   │
  │  config.json                  설정값 저장소(자동)  ❌ 건드리지 말 것 │
  │  optimize_strategy.py         AI 월간 복기 엔진    필요 시만   │
  └──────────────────────────────────────────────────────────────┘

  ※ config.json은 백테스트와 AI 복기가 자동으로 갱신합니다.
     사람이 직접 편집하면 두 파일의 결과와 불일치가 생길 수 있습니다.


================================================================
  📅 매월 말일 루틴 (월간 정기 점검)
================================================================

  실행 시점 : 매월 마지막 주 금요일 권장
  소요 시간 : 약 10~20분
  실행 환경 : VS Code 터미널 (PowerShell)

  ┌──────────────────────────────────────────────────────────────┐
  │  STEP 1. 백테스트 실행                                        │
  │    python SOXL_VIX_SIGMA_BACKTEST.py                         │
  │                                                              │
  │  → 4년치 시장 데이터 기반으로 최적 VIX 배수 조합을 탐색          │
  │  → 현재 config.json 설정값의 수익률 / MDD / Calmar 확인        │
  │  → 최적 배수 조합 결과 검토 후 저장 여부 결정                   │
  │     y 입력 : config.json 자동 갱신                            │
  │     n 입력 : config.json 변경 없이 유지                       │
  │                                                              │
  │  💡 90일 롤링 시그마는 매달 달라지므로 월 1회 재최적화          │
  │     필요. 한 달 전 최적값이 이번 달엔 최적이 아닐 수 있음.       │
  ├──────────────────────────────────────────────────────────────┤
  │  STEP 2. AI 월간 복기 실행                                    │
  │    python optimize_strategy.py                               │
  │                                                              │
  │  → Hermes AI가 한 달간 매매 기록(ledger.json)을 분석           │
  │  → 실탄 소모 속도, 진입 타점, 시장 국면 평가                    │
  │  → 핵심 변수 1개만 미세조정 (한 달에 2개 이상 변경 금지)         │
  │  → 리포트 및 변경 이유 확인 후 저장 여부 결정                   │
  │     y 입력 : config.json 추가 미세조정 + GitHub 자동 동기화    │
  │     n 입력 : config.json 변경 없이 유지                       │
  └──────────────────────────────────────────────────────────────┘

  전체 흐름 도식:

    SOXL_VIX_SIGMA_BACKTEST.py   ← STEP 1
            ↓  "y" 입력
        config.json  (통계 기반 재최적화)
            ↓
    optimize_strategy.py         ← STEP 2
            ↓  "y" 입력
        config.json  (AI 미세조정) → GitHub 자동 동기화


================================================================
  📅 매년 1월 초 추가 점검 (연간 정기 점검)
================================================================

  ※ 월간 루틴(위)과 별도로 연초에 아래 항목을 추가 검토합니다.

  ┌──────────────────────────────────────────────────────────────┐
  │  CHECK 1. SAFETY_BOUNDS 범위 재검토                           │
  │    → 1년간 시장 국면 변화를 반영해 탐색 범위 재설정 여부 검토    │
  │    → 수정 필요 시 SOXL_VIX_SIGMA_BACKTEST.py의                │
  │       SAFETY_BOUNDS 딕셔너리만 수정                           │
  │                                                              │
  │  CHECK 2. 홀딩 기간 / 매수 횟수 필터 점검                      │
  │    → HOLD_DAYS, 매수 횟수 필터(170~240회) 전략 목표와          │
  │       일치하는지 확인                                         │
  │                                                              │
  │  CHECK 3. 수수료율 확인                                       │
  │    → 나무증권 우대 수수료 변경 여부 확인 후 FEES 값 갱신         │
  └──────────────────────────────────────────────────────────────┘

  💡 연간 점검은 백테스트 파일(SOXL_VIX_SIGMA_BACKTEST.py)만
     수정하면 됩니다. config.json은 직접 편집하지 않습니다.

【수정이 필요한 상황별 작업 위치】

  상황                                    수정 파일
  ──────────────────────────────────────────────────────────────
  탐색 범위 변경 (MULT_NORMAL 등)         SOXL_VIX_SIGMA_BACKTEST.py
  수수료율 변경 (FEES)                    SOXL_VIX_SIGMA_BACKTEST.py
  홀딩 기간 변경 (HOLD_DAYS)             SOXL_VIX_SIGMA_BACKTEST.py
  매수 횟수 필터 변경 (170~240회)         SOXL_VIX_SIGMA_BACKTEST.py

  AI 분석 저장 로직 수정                  optimize_strategy.py
  Discord / Git 설정                     환경변수 또는 GitHub Secrets
  실제 운용 설정값 확인                   config.json (읽기 전용으로 참고)


----------------------------------------------------------------
【SAFETY_BOUNDS 설계 원칙】

  백테스트 파일(SOXL_VIX_SIGMA_BACKTEST.py) 안의 탐색 범위:

    MULT_NORMAL  : 0.65 ~ 0.85   평시 시장 (VIX 20 미만)
    MULT_FEAR    : 1.95 ~ 2.45   공포 시장 (VIX 20 이상)
    MULT_EXTREME : 2.50 ~ 2.75   극단 공포 (VIX 30 이상)

  설계 원칙:
    ① MULT_EXTREME 하한(2.50)은 반드시 MULT_FEAR 최대(2.45)보다
       커야 합니다. "극단 공포 배수 > 공포 배수" 논리를 보장합니다.

    ② config.json의 MULT_EXTREME 초기값(2.40)은 첫 백테스트 실행 후
       자동으로 2.50 이상으로 갱신됩니다. 직접 수정 불필요합니다.

    ③ 탐색 범위를 바꾸고 싶을 때는 반드시 백테스트 파일의
       SAFETY_BOUNDS 딕셔너리만 수정하세요.


----------------------------------------------------------------
【보안 설정 위치】

  키/시크릿                저장 위치
  ──────────────────────────────────────────────────────────────
  GEMINI_API_KEY           PowerShell 환경변수 (시스템 등록)
  DISCORD_WEBHOOK          GitHub Secrets
  DISCORD_USER_ID          GitHub Secrets

  ※ 위 값들은 절대 코드 파일에 직접 입력하지 마세요.
     GitHub에 올라갈 경우 외부에 노출됩니다.

  ※ GitHub Actions 워크플로우(.yml)에서 Git push 인증은
     반드시 github.token(기본 내장 토큰)을 사용하세요.
     외부 PAT(Personal Access Token)를 URL에 직접 삽입하면
     인코딩 오류로 push가 실패할 수 있습니다.

     올바른 표준 구조:
       - uses: actions/checkout@v4
         with:
           token: ${{ github.token }}
       - run: git remote set-url origin
               "https://github.com/${{ github.repository }}.git"
       - run: git push

【주의사항 요약】

  ✅ 파라미터 수정은 백테스트 파일(SOXL_VIX_SIGMA_BACKTEST.py)에서만
  ✅ 매월 말 백테스트(STEP 1) → AI 복기(STEP 2) 순서 준수
  ✅ 저장 여부는 결과를 충분히 확인한 후 "y" 입력
  ✅ GitHub Actions 인증은 github.token 사용 (외부 PAT 금지)
  ❌ config.json 직접 편집 금지
  ❌ API 키 / Webhook URL 코드에 직접 입력 금지
  ❌ 한 달에 2개 이상 변수 동시 수정 금지 (AI 복기 원칙)
